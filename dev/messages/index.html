Messages

Besides traits, some widgets exchange custom messages with the host: a heartbeat, samples of a chart, a sync_request from a new view. Each widget class lists its messages in the contract:

using AnywidgetInstruments
[(m["type"], m["direction"]) for m in message_specs("TrendChart")]
5-element Vector{Tuple{String, String}}:
 ("hb", "host-to-front")
 ("append", "host-to-front")
 ("snapshot", "host-to-front")
 ("clear", "host-to-front")
 ("sync_request", "front-to-host")

Building messages

A Message (from Anywidget.jl) is a JSON content and a list of binary buffers. Builders check the message type against the contract:

trend = TrendChart(; pens = [Dict("name" => "Level"), Dict("name" => "Temperature")])
m = append_message(trend, [[1.7e9, 1.7e9 + 1], [1.7e9]], [[0.5, 0.6], [20.0]])
m.content
Dict{String, Any} with 2 entries:
  "type" => "append"
  "pens" => Any[Any[0, 2, 2], Any[1, 1, 1]]
length.(m.buffers)   # float64 times and float32 values for each pen

encode_buffer (from Anywidget.jl) writes the buffers of other messages: numpy-style dtype, little-endian whatever the host.

Sending messages

send_message (from Anywidget.jl) hands a message to the transport of the host, with the widget's message id (w.id). The Kaimon Slate extension installs one when SlateAFM is loaded; another host installs its own:

set_transport!((id, msg) -> my_send(id, msg.content, msg.buffers))

Heartbeats

A host announcing heartbeats sets _session and _heartbeat on the widgets, then sends heartbeat_message every _heartbeat seconds to at least one widget of the session. Without heartbeats, the widgets never show ⚠ NO KERNEL or ⚠ STALE.
